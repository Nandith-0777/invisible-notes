# Ubuntu binary installer

This experimental amd64 `.deb` supports Ubuntu 24.04 with Mutter
`46.2-1ubuntu0.24.04.18` and GNOME Wayland. It bundles Electron, the application,
and the prebuilt capture companion. End users do not need Node.js, npm, Git,
or a compiler. A restart is required after installation or removal.

The exact Mutter dependency intentionally prevents installing this preview on
an untested revision. A new compositor revision requires rebuilding and testing
another installer. Do not force dependency overrides.

For a complete source build on Ubuntu 24.04, install Node.js 22 and run:

```sh
npm ci
npm run dist:ubuntu
```

This prepares the native build dependencies with sudo, compiles the exact
Mutter revision, exports its corresponding source and symbol-derived runtime
dependencies, then assembles the `.deb`. Build prerequisites are for developers
and CI only. The GitHub release workflow runs this on `ubuntu-24.04`.

All platform installers share the version in `package.json`. Ubuntu maps
prerelease `-` to Debian `~`, with an Ubuntu package revision, while its download
filename retains the common app version. The previously tested local
`1.2.2+ubuntu24.04.2` package remains documented in the historical VM report.

For an existing verified native build, use `prepare-companion.py` to export the
binary, source and dependency manifest, then build on Ubuntu using `build-deb.py`, supplying the Electron distribution and
an external companion artifact directory containing `manifest.json`,
`libmutter-14.so.0.0.0`, and `mutter-source.tar.xz`. The source archive must contain
the corresponding modified Mutter source and build scripts, excluding generated
build products. The builder verifies the manifest hash and source archive. Its manifest must
include `runtimeDependencies` generated by `runtime-dependencies.py` on Ubuntu
using the native library and Electron runtime. This uses Debian symbol metadata
to include dependencies that were installed indirectly during development.

```sh
python3 packaging/ubuntu/build-deb.py \
  --electron /path/to/electron/dist \
  --companion /path/to/companion \
  --output dist
```

Install with Ubuntu's package installer, or from a terminal:

```sh
sudo apt install ./Ghost-Notes-1.3.0-beta.1-ubuntu-24.04-amd64.deb
```

Then save work, restart Ubuntu, and open **Ghost Notes** in the launcher.
The app refuses to open protected notes until the companion is verified active.
No desktop restart is initiated by package scripts. On removal, the original
Ubuntu library is restored; personal notes remain in the user's profile.

```sh
sudo apt remove ghost-notes-ubuntu
```

The integration uses a package-owned `dpkg-divert` and atomic replacement of the
core library. The original is diverted outside the library search directory so
`ldconfig` cannot accidentally select it during activation. A matching root-owned manifest records its hash. Runtime checking
requires the matching package version, hash, loaded library inode, and opt-in
Wayland GNOME session. Unrelated library diversions and changed files are rejected.
Activation failures restore the stock library when creating the diversion.

References: [Debian maintainer scripts](https://www.debian.org/doc/debian-policy/ch-maintainerscripts.html)
and [dpkg-divert](https://manpages.debian.org/unstable/dpkg/dpkg-divert.1.en.html).
